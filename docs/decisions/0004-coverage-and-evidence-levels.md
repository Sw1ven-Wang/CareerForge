# ADR 0004：按目标位置覆盖规划，保留明确数量要求

日期：2026-10-17。实施范围为源码审查建议的 A 包，覆盖 ADR 0003 中“所有计划必须先达到项目数量”的默认安排。

## 决定

- 新建方向默认 coverage：项目数量是收集偏好。选择的技术必须在选择的审核项目中有有效代码位置依据。
- strict_count：用户明确要求达到数量时，仍按原数量阻止计划，不能用确认字段绕过。
- 未保存 collection_policy 的历史方向按 strict_count 处理，不迁移或降低已有要求。
- 老客户端显式传 target_count 且未指定策略时，继续使用 strict_count；新页面明确提交策略。
- coverage 模式数量未满足时，启动计划必须明确确认当前范围；缺少位置依据仍拒绝。
- 覆盖表展示每项技术的位置覆盖缺口。默认调研只针对缺口；用户也可明确选择补充技术。
- 数量达标但目标仍缺位置依据时，当前有界批次可继续审核，仍不增加调用预算。

## 源码定位

文件路径评分与正文锚点评分分离。正文并列时使用较早位置，Python 优先读取包含锚点的函数/类范围。每文件最多两个非重叠窗口，不同文件优先获得第一个窗口。

保持至多六个源码窗口、每个最多 70 行 / 2600 字符、至多两份 README / 每份 5000 字符。只有路径命中的 Python 文件返回受限符号摘要，不伪造已读源码。它不是 B 包的自主代码调查工具。

## 证据等级

服务器分别记录：
- location：精确且唯一的引用定位已校验。
- semantic_support：模型解释尚未独立核验。
- runtime：未取得运行观察。

模型不能自行将后两项提升为已验证。覆盖表当前表示位置覆盖，不是机制支持率或能力掌握率。历史不可变产物只增加保守展示信息，不改写历史结论或供应商收据。
