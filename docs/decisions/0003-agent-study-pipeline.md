# 0003：以需求和开源实现为中心的 Agent 学习流程

日期：2026-10-13。覆盖旧六模块导航与自动岗位采集安排，保留历史记录及接口兼容。

人工导入岗位正文 → Extract Agent → 技术需求版本（了解/熟悉/掌握） →
Research Agent（技术关键词、GitHub 公开仓库） → 候选 →
Review Agent（固定 commit 文档与代码证据） → 强相关项目库 →
用户选择学习意图 → Plan Agent → 分级模块计划 →
Tutor Agent ↔ 用户问答、图示、技术亮点索引 ↔ IDE 精确定位。

需求深度是学习目标，不是用户当前能力。原文明确要求与模型推断分开记录。
新需求版本不沿用旧审核结论；旧产物保留为历史。

增加 study_tracks 和不可变 study_artifacts，严格 Pydantic 合同。
不同 Agent 是版本化 Python 阶段及不同职责提示，复用队列、租约、outbox、
预算和模型收据，不引入 LangGraph。

Research 提出最多 3 个查询，只允许 GitHub 公共 API；可串联最多 5 次 Review，达到目标即停止；候选去重，保留查询和观测时间。
Review 每次读取一个固定版本。弱相关/不确定不入库；
强相关且有可校验源码匹配、可识别许可证、非归档非 fork 才自动入库。
人工导入项目可送审，不冒充通过审核；人工副本保留远端状态未验证限制，许可可识别且源码匹配才可纳入。所有代码未经执行。
默认目标 5 个不同仓库，可改为 1–10；不足时不生成计划，不无限搜索或增加额度。

学习意图：项目构建、整个项目、技术设计、函数实现；后两项必须填写目标。
计划只有所选技术和审核通过的项目，具有父子模块、前置关系、步骤、成果及验收条件。
亮点和 Tutor 的源码解释均连接固定版本、文件、行区间；自动跟随可关闭。
Tutor 使用有界只读代码工具，保留同计划/模块的问答历史；
支持文字、结构化图示（SVG）和表格，首版不声称具备位图生成能力。
不执行模型 HTML/JS。未读代码不生成源码事实。
用户标记完成属于自报进度，不代表职业能力正式验收。
本机 IDE、补丁审阅和命令逐条确认继续保留。

开发只做针对性离线链路验证，不追加真实模型调用、不执行导入项目代码。
GitHub 限流与 incomplete_results 必须保留：
https://docs.github.com/en/rest/search/search#search-repositories
