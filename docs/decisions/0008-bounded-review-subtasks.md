# ADR 0008：有界审核子任务、预算预留结算与取消传播

日期：2026-10-17。状态：已实施；补充 ADR 0007。

## 范围与入口

新增固定版本项目审核批次，作为持久化子任务的首个业务落点。在 `/agent` 的研究审核区展开“用子任务审核固定版本（最多两个）”，选择 1–2 个候选并确认调用额度。API 为 `POST /api/v1/study/tracks/{id}/review-batches`。

候选须已有本人可读的导入快照，或之前审核留存的固定源码快照；批次不临时拉取可变分支。现有 Research 自动发现和审核仍沿用原顺序流程。本轮不提供模型任意递归分派，也不扩大命令、文件写入或网络工具权限。

父任务版本为 `agent-study-review-batch-1.0`，子审核为 `agent-study-review-child-1.0`。其他角色版本沿用 ADR 0007。父任务编排和汇总由确定性代码执行，调用模型次数为零；子任务复用有界源码调查与审核。

## 子任务合同与执行

合同冻结父任务、当前需求版本、单个候选及快照哈希、需求键、来源指针、只读工具白名单、调用额度、每次输出上限、统一截止时间、输出结构和停止条件。子任务没有父任务完整对话或其他子任务上下文。服务器重新构造并比对整份输入合同，不能由模型自行改写范围、模型或预算。

最多一层、两个子任务，每个 1–3 次模型调用；根任务总额度 1–6 次，每次 512–8192 输出 token，且不高于配置上限。批次截止时间为创建后 15 分钟，包括排队时间。创建子任务、预算预留及 outbox 同事务提交；已有相同任务键只在合同和额度完全一致时复用。

父任务分发后进入 `waiting_children` 并释放 Worker。子任务可由两个 Worker 并发执行；最后一个子任务结算时，事务内将父任务唤醒为 `queued` 并新增 outbox。父任务恢复后读取阶段产物，重新核对需求、来源、候选、源码快照和引用，发布审核与可能的项目入库。发布阶段有唯一键，可重复投递但不重复入库。

## 预算不变量

`calls_reserved` 表示已占用的调用额度，`held_calls` 表示已为尚未发出请求预留的额度。根任务始终满足 `calls_reserved + held_calls <= call_budget`。

1. 分派之前，将子任务额度从根可用额度移至预留；没有预留不能排队执行。
2. 发出模型请求前，在父子事务锁下将一份预留转为已占用，同时保存子任务调用收据。
3. 子任务终止时只释放尚未使用的预留，记录结算时间；重复终止不会重复释放。
4. 请求已经发出、失败或结果未知时，额度不退款，也不自动重新调用。迟到响应可补记计量，不能绕过租约发布产物。

调用额度不是货币余额。供应商返回的输入和输出 token 单独记在收据中；每次请求输出上限由适配器传递并检查，但不能保证供应商的实际计量一定遵守上限。本轮没有计价、金额预扣或账单对账功能。

## 取消、截止与发布屏障

统一采用根任务先于子任务的数据库锁顺序。取消父任务递增其 epoch，并取消所有仍活跃的子任务、撤销子租约、结算未用预留；单独取消子任务不取消兄弟任务。reaper 检查所有非终态根任务的截止时间，含 `waiting_children`，截止后终止父任务并向下传播。

子任务只写自己的暂存产物，不能直接发布业务审核或入库。即使某个子任务已经完成，父任务随后被取消，其暂存结果也不能独自进入项目库；父任务发布前持有有效租约并重新校验所有输入。取消无法收回供应商已经接收的 HTTP 请求，但会阻止下一次调用及迟到业务写入。

## 持久化与展示

迁移 `cf201017a002` 新增父任务、截止时间、预留额度及 `run_allocations` 结算账本，含同用户父子外键、唯一任务键和预算约束。先备份数据库，再升级迁移，最后更新 API/Worker/dispatcher。降级遇到活跃子任务或未结算预留会明确拒绝。

运行详情展示根总额度、已占用、预留、可用额度，以及每个子任务的状态、分配、已用、释放和供应商收据。保存 `task.created`、`budget.reserved`、`budget.consumed`、`budget.settled`、`task.result_ready`、`task.joined` 等事件。
