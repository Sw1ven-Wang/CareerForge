# 1.6.2 剩余边界与未验证能力

本轮结果以根目录 `DELIVERY_REPORT.md`、`RELEASE_STATUS.json` 和 `VALIDATION_REPAIR_1_6_2.md` 为准。原 1.6.0 的完整差异说明保留在 [历史文件](history/v1.6.0/KNOWN_GAPS.md)，历史通过项不自动成为本版通过项。

- **完整业务闭环未证明。** 模型测试覆盖冻结来源的分析/审核结果消费、路由、计划提议及一段 Tutor→反馈→反思链路；没有一个连续真实案例完成职位导入、需求抽取、自动研究审核入库、采纳计划、练习作答与记录、进化晋升。源码引用不是 UI 高亮交互证据。详见交付报告的八阶段清单。
- **不是原应用原地替换。** 本包沿用独立 CLI/API 项目，不补回原 Vue/Tauri UI、全部旧 API 或完整旧数据库迁移。升级真实数据库前仍需备份和隔离验证；本次未新增 Alembic 迁移。
- **来源与历史上下文保持保守边界。** 未明确范围、冲突焦点和无法在当前授权事实中解析的指代可能需要澄清或返回缺口。旧问题、旧回答和旧符号不作为新用户输入外发。旧不安全的未完成合同不能新调用模型；已完成收据的兼容不代表增加授权。
- **补丁结果不替换原盲测。** 1.6.1 的 P06 失败、R08 分数回归及其他质量遗漏保留。1.6.2 将任务类型、检查项与评分规约的跨字段要求写入新版本合同，并补全编辑动作家族弃权；对原 R08 不强制路由。12 项重测采用预先冻结的新评分标准，不能直接与原分数作数值对比，也不能把新模型选择归因于代码。
- **真实语义质量结论有明确分母。** 新持出案例、旧已知回归、规则路由、无模型模板与模型调用分别计数。有限合成仓库和文件桥不能证明真实用户学习收益、任意仓库正确率、生产 HTTP 行为或后端模型身份。供应商 token、账单费用与独立身份认证未提供，不能估造。
- **进化不保证成功。** 只有真实候选通过现有授权和晋升门禁并发布后，才产生有效 C 对照。缺授权、门禁失败或未发布不是通过，不能通过手工覆盖策略伪造收益。
- **学习任务仍需实际学习者验收。** 结构化输入、验收条件、缺口与偏好投影可复验，但不等于教学收益已经测量。本人声明的独立尝试不监控外部设备，复习日期也不是外部提醒。
- **本轮未重验生产基础设施。** 当前工作空间没有可用的原生 PostgreSQL/Redis 服务，Docker 受限且未绕过。因此 27 项生产标记用例保留排除，SQLite 并发与锁序审计不等于真实分布式锁验证。历史 PG/Redis 结果明确属于旧版本。
- **可选依赖另列证据。** 最终版 11 项真实语法库和 2 项已安装 Pi SDK 测试使用隔离依赖、SDK 内的确定性模型，不是付费推理。其 13/13 与原环境全量的 13 个跳过分别报告，不能改写后者。前次补测两份 raw 日志被后一次覆盖，无法恢复；最终版 raw/JUnit 完整，前次聚合与依赖记录保留。
- **部署、容量和供应链没有新承诺。** 未部署、推送、执行远程 CI、压测或灾难恢复演练；没有完整代码覆盖率百分比。npm 锁的不可用版本已按相同 integrity 修正，Python constraints 和容器基础镜像仍不是全链路 hash/digest 锁。
- **既有产品范围继续适用。** 不包含任意安全规则改写、自动远端仓库轮询、通用语义类型转换、本机 IDE 同步、企业 IAM 或合规认证。详细历史范围见上方链接，不能把本轮机制修复说成这些功能均已实现。
