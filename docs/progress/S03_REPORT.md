# S03：M1 导入与 M2 岗位要求分析（离线范围）

日期：2026-10-12。用户指定 Agent 开发方向、只做离线验证、使用 joblearn 个人材料；沿用 Python 显式阶段函数和 PostgreSQL 事实，不使用 LangGraph。

## 实现结果

- 文本及附件导入：UTF-8 txt/md/log/json/py、安全 JUnit XML，最大 1 MiB；拒绝 ZIP、二进制、非法语法、DTD/实体/XML 外部读取。正文规范化后最多 100000 Unicode 字符。附件未绑定时 24 小时过期，一个附件只绑定一个根来源、允许同根多个版本复用。
- 持久化岗位版本、要求集合、要求、引用、疑似重复对、追加决定和冻结报告。读取同时校验 owner、根、快照及附件可用性；撤销立即阻止内容、引用、旧报告和旧幂等输入回放。物理清理仍属后续维护阶段。
- 显式阶段为输入验证、逐份离线提取、引用验证、程序统计与冻结报告。最多 20 份输入，调用预算固定；使用 FakeModel 和统一调用账本，无真实供应商调用。失败 JD 保存错误，其他有效 JD 可继续；没有有效分母时运行失败并保留诊断报告。
- `skills-v1` 字典区分工具与能力；要求区分职责、必须、优先和推断，保留任选语言条件组；引用按规范原文 Unicode 左闭右开区间逐字验证。规则仅提取字典命中项，遗漏 Go、业务语义等属于当前基线限制，不能作为真实模型质量证据。
- 来源 ID、规范 URL、完全一致内容哈希先合并；相似正文或同标题只产生候选。相似度使用有界字符 shingle 集合，不自动合并。重复/不同/未知决定追加保存，验证传递性矛盾，同一候选对不得同时选择多个决定版本；新报告只冻结显式选中的决定。
- 分母是去重后、提取完成且岗位类别/地区符合目标范围的岗位发布代表；一个岗位同概念重复提及只计一次。面经、个人材料、推断项不进入明确技能分子；地区组可重叠。缺失经验、日期和类别保留未知。
- 更正以集合 revision 防并发覆盖，追加新要求和引用、保留被替代项及原因。旧报告不变，新报告包含集合 revision 和配置指纹。
- `/market` 展示运行事件、输入清单、岗位分母、技能数量、要求类别与来源、引用定位、范围排除、人工更正及重复决定。数字来自服务端固定计算，解释是明确标注的离线规则说明。

主要新增接口：`/attachments`、`/market-research-runs`、`/market-reports`、`/requirements/{id}`、`/requirements/{id}/corrections`、`/duplicate-candidates`、`/duplicate-candidates/{id}/decisions`；API/OpenAPI 与生成的前端类型已同步。业务写入使用幂等键，跨用户资源返回 404。
