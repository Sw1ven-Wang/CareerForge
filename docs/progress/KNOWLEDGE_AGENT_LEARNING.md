# 知识库自主检索与带原文依据的学习说明

日期：2026-10-13。入口 `/studio` → 项目 Agent → “学习说明 · 自主检索”。

## 使用

1. 选择已有学习计划和目标，选择或创建自己的工作区。工作区用于保存说明记录；学习模式不读取或发送其中的代码文件。
2. 可选择最多 10 个已索引项目版本；留空时使用当前用户的全部已索引版本（超过 10 个需缩小选择）。本轮范围在提交时冻结，不会自动导入更多仓库。
3. 选择 2–4 次模型调用上限，默认为 4 次；输入希望理解的机制，或留空使用当前学习目标。
4. 点击“检索并生成学习说明”。这才会调用已配置的模型；每次 `gpt-6.1-sol low` 请求最多 2048 输出 token，没有模型调用自动重试。最多 4 次请求不是金额上限，当前供应商费用未定价。
5. 查看学习点、连续原文摘录、阅读顺序、小型迁移练习、自检问题和未知。点击“定位原文”打开固定 commit 的文件，按该摘录的实际行号高亮。

说明保存在工作区，明确记录对应目标版本、模型、调用用量、引用和检索轨迹。未完成任务刷新后可恢复查看运行进度；同一工作区不允许同时发起两个学习说明任务。失败或取消显示状态，不伪造报告。

“代码补丁助手”保留原来的单次调用模式，继续由用户审阅应用补丁、逐条确认命令。学习模式只读，不输出补丁或命令，不改计划、不自动标记已掌握。

## 自主检索实现

显式 Python 工作流 `learning-studio-research-1.0`，通过现有 OpenAI-compatible provider、Celery 及 PostgreSQL 阶段产物执行，没有新增 LangGraph 或付费检索服务。

初始根据目标与请求进行一次确定性的词法检索，提供候选元数据。随后由模型自主决定工具与参数，可调整查询词、选择原文片段和追踪相关结构；不是预设固定文件或代码路径。

三个只读工具：

- `search_code(query)`：仅检索冻结范围，返回最多 6 个候选的路径、符号、commit、行号与片段 ID。检索结果不是可引用正文。
- `read_code(chunk_id, start_line, end_line)`：只允许本轮已发现片段；验证文件 / 片段哈希后读取，创建精确的代码引用。每份最多 3500 字符，过长只取完整行并标记截断；可指定片段内的后续范围。
- `related_code(chunk_id)`：只允许已发现片段，返回最多 6 个静态包含或同名引用候选。候选仍须通过 `read_code` 实际读取后才能引用；不证明运行时调用。

每轮最多 3 个工具调用，总计 8 个（含初始检索），最多 4 份已读引用；模型最多 3 轮工具决定 + 1 次最终说明（受所选总调用上限约束）。提示词最多 45,000 字符，代码上下文最多约 14,000 字符。当前知识库仍采用结构 / 词法检索，未启用向量检索或模型重排序。

外部模型 I/O 在数据库事务外执行，调用走现有预算与 receipt 入口。每次调用前保存 attempted 标记，结果与工具观察分阶段保存；恢复复用已保存阶段。已尝试但结果未保存的调用停止自动继续，避免重复收费。取消、过期租约或撤销输入后不得发布迟到说明。

## 原文验证与权限

最终结构化说明的每个学习点必须使用本轮实际读取取得的 citation ID，以及其中连续、不改写的原文摘录。后端再次核对来源及内容哈希，验证摘录为原文子串，计算字符偏移与绝对行号。文件路径和 commit 由后端填充，不采信模型编造的定位。

引用正确不等于解释语义一定正确。页面标记原文已校验，解释仍待核对；静态引用候选、模型推测及真正运行证据保持区分。摘要只概括目标与覆盖范围，代码事实应写入带证据的学习点。

未读取到原文时，不进行最终事实生成；保存系统生成的“依据不足”说明与缺口，返回部分完成。模型也可以主动声明依据不足。非法原文、未读引用、非法结构或不完整输出会使本次失败，不自动再调用修复。

资料范围和所有工具均校验用户归属。仓库文本、描述与工具观察作为不可信资料处理。学习模式没有宿主文件、Shell、下载、编辑和执行工具。发布后每次读取工作区仍校验说明使用的目标与引用；依据撤销或损坏时隐藏历史说明正文与摘录。
