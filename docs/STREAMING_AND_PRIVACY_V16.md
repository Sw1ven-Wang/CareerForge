# v1.6：逐块回答与个人数据治理

## G10：不是“整份生成后切片”

生产 `ConversationService.process` 消费 `AnswerService.iter_tutor`。每次真实 `ModelGateway.call` 只允许 `SingleAnswerOutput.blocks` **恰好一个完整块**，使用独立的 `tutor.block:N` 付费收据与任务预算。模型的原始 token 不向 SSE 透传。

每块依次执行：

1. 从当前有效 Publication 重新读取唯一 FactAtom、条件和该 Claim 的实际支持 Evidence；冻结缓存正文不构成授权或事实依据。
2. 生成一个原子块；条件、项目、版本、事实绑定必须匹配。改写另走独立语义检查，高风险改写只可降为已审核原文或证据不足。
3. 在单独事务中再次校验租约、所有权和依赖，保存不可变 AnswerBlock，建立 `teaches_from` 与精确 `states_fact` 阻断边。
4. 持久化 `answer.block.validated → answer.delta → answer.block.completed`，事务提交后才请求下一块。所有块提交且最后依赖复核成功后才发 `answer.completed`。

每个已付请求的 key、严格输出 schema、来源合同、依赖闭包摘要、隐私 generation 和模型 profile 都绑定 request hash。实际发出的可选 TopicLink/Facet 正文也显式绑定，不能依赖 Publication 的 impact-only 边；首次冻结的引用不会在重取知识包时缩减。预约事务另保存只含 receipt ID、引用和摘要的 model-access 见证，供后续精确清理已完成响应中的派生正文。已付未提交块可复用原收据；游标重放不调用模型。预算不足、取消、来源撤销或后续块失败会保留已提交块并中断，不虚称整份回答完成，也不自动重付。

`AnswerService.tutor` 仅是供评测等调用的收集接口；对话生产路径不先收集整份答案。教学模板仅提供组织偏好，不能绕过 Guard。只有明确的无付费任务才使用标示清楚的确定性证据模式。

来源在最后游标之后失效时，读取流会幂等追加新的持久失效通知；不是仅在重放旧序号时才发现。隐私擦除也追加失效通知并移除相应正文。已显示、下载或发往第三方的内容不能被软件“召回”。

## G14：导出、明确确认、可恢复清理

- `GET /api/v1/privacy/export`：导出本人拥有的私人/工作区资料，不递归导出他人的私有源；凭据、确认 nonce 和原始供应商响应正文不在导出中。公共知识不作为个人删除范围。
- `POST /api/v1/privacy/deletion-proposals`：返回范围、行数快照、保留例外、计划摘要、短期有效的一次确认 nonce。
- `POST /api/v1/privacy/deletion-proposals/{id}/confirm`：必须同时确认 nonce、计划 hash 和不可逆性。范围是确认时全部个人正文，包括提案后新增资料。
- `GET /api/v1/privacy/deletion-proposals/{id}`：本人可在封锁期间继续查询最小操作状态；不能通过该控制面读取正文。

清理是三阶段可重试状态机：

1. **单独状态事务**独占锁定 PrivacyState，提升 generation 并设置 blocked；此事务不持 funding/run 锁。
2. 复用运行时结算取消本人任务及本人私域内的受托任务；按明确公共共享政策解除本人订阅。撤销私人依赖对象，擦除源文件、对话、学习资料、编码快照/收据、模型响应、阶段产物、旧导入正文、私有分类投影以及检索派生内容；禁用维护计划。失败不解除封锁。
3. 清理仅含相关本人/对象引用的缓存，完成后才解除封锁。旧私人域成为已清理的工作区墓碑，创建新的私人域；新资料需要新的预算授权，旧对象和运行不会复活。

普通私有读取和写入持 PostgreSQL `FOR SHARE` 隐私栅栏直到事务结束；状态擦除只在第一阶段取独占锁。缓存发布亦持短共享栅栏。异步确认的阻塞 SQL 阶段在线程中执行，避免同事件循环等待锁阻塞 Redis 发布。对两个不同私域的读取共享锁兼容，不采用互相反序的独占读锁。

模型网关接收**调用者明确给出的可信 `access_dependencies`**，不从模型文字猜授权对象。预约、外发前、响应持久化时都重新验证阻断闭包和当前 Funding 来源白名单。已在途请求不能撤回；若来源、权限、隐私 generation 或闭包发生不允许的变化，返回正文只会被丢弃，保留最小数字用量/请求 hash，不回填被擦除的数据。

### 跨人派生副本的有界范围

可信反向依赖证明来自待删私源的其他人 `answer_block`、`selection_manifest`、`comparison` 渲染副本会脱敏并撤销；对应块事件、源读取副本、能够精确定位的阶段正文和模型响应也清除。保留另一人的问题、无关块、无关阶段、手写资料和账务；反向遍历不会进入公共知识域。不能证明来源的外部副本不被假称已删除。

### 保留与例外

这是**运营数据策略，不是法律意见或合规认证**。继续使用的账号认证、假名化（非保证匿名化）账务计数、请求/授权 hash 与固定来源/角色范围、撤销依赖墓碑保留到另行关闭账号；删除提案审计默认保留 365 天，管理员可运行到期清理接口。管理员可登记有明确到期日的保留例外；存在例外时拒绝删除，并向本人披露，而不是暗中保留已声称擦除的正文。

不承诺清除第三方模型供应商的副本、已经下载的导出、外部个人笔记或备份介质。备份轮换和账号最终关闭需运营方另行执行。当前为事务式在线清理，非海量离线归档平台；失败保留封锁及可重试状态，不报告部分清理为完成。

## 验证边界

`validation/v16/` 保存本轮新证据；`validation/current/` 是旧恢复点证据。测试使用明确标识的 synthetic provider，不代表真实模型回答质量，不请求付费模型。原生 PostgreSQL/pgvector/Redis 测试是真实服务，但**不是 Docker 测试**；当前 dot 沙箱的 Docker 阻碍与旧 Docker 可复现脚本说明仍适用。
