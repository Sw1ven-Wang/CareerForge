# 撤销与正文清理

来源、附件、个人材料和候选仓库的删除首先撤销读取资格。报告、目标、学习单元、提交和确认沿引用链重新检查 owner、版本和上游可用性；持久化幂等响应也重新鉴权。列表跳过失效衍生产物，保留其他有效项目可用。终端运行摘要只提供安全状态与引用身份。

maintenance_service.clean_once 使用持久化扫描游标和受限批次，清理撤销来源正文、附件字节、个人版本正文、受影响的阶段/事件/产物与幂等副本；保留业务身份及费用回执的必要元数据。dispatcher 可定期执行并在失败后重试，任务只有相关正文实际清理后才标记 erased。

**开发库默认 `CAREERFORGE_MAINTENANCE_ENABLED=false`。** 自动审批曾拒绝在已有开发库重置全局游标并批量擦除的测试，因为可能影响既有撤销材料。已改为新建独立 validation 数据库做验证；没有绕过拒绝清理旧库。逻辑撤销仍立即阻断访问。实际部署启用物理清理前须确认其保留策略和备份，不能将开发库批量擦除作为回归步骤。

清理不修改 joblearn 原始目录，也不会删除用户电脑上的原材料。已有备份与用户另存副本不可能被数据库撤销自动消除；备份仅存 private，保留和销毁由部署者管理。外部观测服务未启用，没有上传私人正文。
