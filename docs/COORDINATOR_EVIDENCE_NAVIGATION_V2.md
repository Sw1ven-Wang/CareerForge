# 覆盖驱动源码导航 v2

新知识构建通过 `coverage_guided_analysis=true` 启用。构建须绑定固定提交、单一来源、单个候选知识单元和已有的自动补证预算。问题显式要求跨文件调用链时，Coordinator 会预留现有自主发现步骤；若已有显式边，则仍按调用方所选边逐一核对。历史构建继续按原版本重放。

## 目标与读窗

第一轮 Brief 保留冻结的全部 JD 要求及逐字原文、分组、深度、条件和来源位置。active_required 用于决定优先读什么，optional_visible 只提供上下文，unresolved_scope 留待进一步明确。NOT 约束仍保存在原要求中，满足一条足够的 OR 分支后无需补查其余分支。

独立审核后最多再安排一对 Analysis/Review，最多四个新行窗。补查记录包含缺失阶段或关系、待核对前提、文件和符号、候选来源、已有已发布证据与窗口预算。独立审核明确提出的有效新行窗先获得预算，剩余窗口参考缺失阶段与已证路径。预算允许时，两端一起安排候选替代边。四个状态分别反映实际读取、Analysis 提出、独立验证和发布。阅读一段代码可以支持调查，是否发布由独立审核决定。

## 机制完成判定

自主发现的目标是调查线索。完整静态路径使用同一固定快照中可组合的已发布跨文件调用与独立源码阶段证据。阶段包括入口、参数校验、派发、结果回填与异常边界。每条阶段证据由已发布 Facet 绑定到支持它的 Claim 和独立源码引用。缺少阶段、连接或异常证据时返回 partial 或 unknown。路径说明仅覆盖静态调用及已审核条件，运行观察仍由运行证据单独建立。

## Learning Plan 输入预算

当原投影超过既有网关请求上限时，新任务使用预算投影。完整 JD、限定、目标和发布身份优先保留，再在仓库与发布间交替挑选可独立引用的已审核事实。事实和全部条件作为一个单位进入目录，重型源码引用及审核元数据仍留在完整授权快照中。模型的事实 ID 和文本 ID 必须在当次可见目录内，通过后还须符合现有逐字引用、目标范围与授权检查。若强制保留的目标本身超过预算，返回明确错误。

API 返回的 coverage、路径及阶段状态可用于查看知识缺口。Tutor 的教学质量通过独立问题评分确认。
