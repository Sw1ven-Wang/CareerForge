# CareerForge 修复与验证报告

交付版本：1.6.2　编制日期：2026 年 11 月 3 日 UTC

本报告同时说明封存的 1.6.1 通用机制修复与持出评测，以及评分后追加的 1.6.2 有界补丁。两个版本的验证分母和结论分别列出。

## 1 结论与发布边界

通用机制修复和盲测后已知缺陷补丁均已通过各自范围内的独立审计；1.6.1 的真实持出评分从预承诺原版 A2 的 2.5556/4 提高到修复版 B 的 3.6111/4，但保留了 1 个退步案例及具体内容缺漏。1.6.2 的 12 个已知路径补丁复测获得 47/48 分，不能替换原盲测，也不能直接比较新旧 P06 分数。

**完整真实业务闭环尚未证实。** 本轮未跑真实 JD 导入与需求抽取，计划未采纳、练习与观察未连接，源码引用不等于浏览器高亮验收；进化候选未改变、门禁不确定、无晋升或 C。主要服务已实现，部分片段有真实模型执行，其余主要由合成模型合同与集成测试支持。

1.6.2 最终全量离线为 976 通过、13 跳过、27 未选；新补丁独立套件 287 通过，旧独立套件 92 通过、1 xfail。封存的 1.6.1 全量为 816 通过、13 跳过、27 未选。工程通过、模型评分、进化收益和生产可用性是不同结论，不能互相替代。

## 2 原版保护与评测隔离

本轮在独立修复副本中完成工作，不覆盖原始 ZIP、1.6.0 基线或原失败证据。原 ZIP 中 1076 个文件与提取的基线树逐一核对 SHA256，0 变更；另有 1106 个原始评测证据文件复核，0 变更。这是两个不同范围的完整性检查，不相加为测试分母。原始 ZIP 的 SHA256 为 e4818e2b7a056647ff4f1eca657fb4b8a16675f014b5742c3557500fe3ff0c1c。

实现与独立机制审计请求配置为 Astra6/max；独立工程测试、真实文件桥生成和独立评分请求配置为 6.1 sol/high。所列名称是请求的模型与推理配置，不等于对实际后端身份的独立认证。真实文件桥进入项目实际 ModelGateway，但不等同于生产 HTTP 提供商链路验证。

原 24 个已知案例只能用于回归。新增 18 个持出案例、参考答案与评分标准由独立评测设计在模型生成前冻结，未经过人工专家金标或学习者收益认证。A1、A2、B 共 54 个匿名评分包冻结后，由新的 6.1 sol/high 模型上下文评分；这是独立模型评分，不是人工评审。预评分清单承诺了匿名顺序与 seed，但没有单独的映射文件哈希承诺。公开的原映射及 seed、原输出清单可重新计算，后来的 MAPPING_VERIFICATION 是事后核验，不能倒称为预评分映射哈希承诺。此后从原 24 个案例中选取的 8 个既有失败案例单独使用新上下文评分并列为回归，其余 16 个原案例未重跑。不得把原案例与新持出案例合并称为全新盲测，不得把重复或重叠的工程测试数量相加作为独立样本总数。

初始原版 A1 的生成上下文此前还承担了 21 次资料准备调用，与全新上下文的 B 不完全同起点。因此，在 B 生成和评分前冻结一次方法修订：仅增加一次全新上下文的原版 A2，完整覆盖同一 18 个持出案例，使用固定原版代码、同一份 pristine 资料快照和同一请求配置。主要版本比较预先指定为 A2 对 fresh B；A1 全部保留并评分，但只作有先前上下文的诊断结果，不按事后分数选择基线。

B 固定持出阶段与后续训练、反思也隔离上下文。预承诺要求固定 B 在最后一条 fixed 请求后停止，由新上下文只消费后续训练请求，不能读取持出输入或最终输出。实际边界为固定阶段最后序号 2028、训练首序号 2029，固定阶段 28 条响应，边界确认时尚无训练响应。只有真实晋升后才允许使用独立新上下文生成 C。

各组内部文件桥仍有上下文延续，不能把此次实验称为无状态提供方测试。调用分母必须包含资料准备、A1、A2、B、训练与门禁、C 以及已知失败回归，不能只统计最终答题调用。B 与 C 的进化对比只有在相同代码下真实候选经过授权、独立门禁并实际发布后才成立；未发布时不能报告进化收益。

### 检索硬范围与推断提示分离

问题不是某个关键词没有命中，而是系统可能把自动推断的主题误当作检索边界，或者在解释意图时混淆明确焦点、可见来源和排序提示。新协调结果分别携带 retrieval_topic_keys 与 topic_hints，直接检索调用中的旧 topic_keys 继续表示硬过滤条件，避免兼容接口无声改变含义。主题与来源的可见性、资助范围、访问依赖以及缓存身份仍是硬约束，模型建议不能扩大这些边界。

用户只是在问题中提到其他项目时，不自动改变当前项目焦点。支持的切换语法要求当前、肯定、未被引用的命令，且指向唯一完整仓库身份；讨论式、否定式、条件式、待批准式、身份不唯一或不可访问的表达均不能扩展范围。切换后删除失效的来源导航信息，避免旧路径和符号继续进入新来源的模型请求。

词法规则对否定、引用和复合动作采用保守处理。出现第二项冲突动作、连接符或相继动作时，不再仅凭首个关键词作高置信路由。算术和路径等合法文本保留正向控制，减少把普通文本误判为复合指令的风险。

来源：README.md；evidence/ASTRA_INDEPENDENT_AUDIT.md 的 M2、M3 与范围审计。
主要代码：services/orchestration.py、services/retrieval.py、services/taxonomy.py、services/conversations.py。

### 最小模型上下文与回答相关性

新回答合同为 atomic-answer-1.6.1。它选择相关事实并为独立语义和相关性审核预留调用预算，将缺少证据、缺少授权和预算不足分别表达，避免把流程限制伪装成知识缺口。缺口经过合并，不以任意生成的解释替代已审阅证据。

教学请求中的焦点只保留允许的呈现布尔值与样式；来源身份由当前、已授权的候选事实包提供。协调请求中的主题和来源列表也必须经过当前可见性与明确访问依赖过滤。原始历史问题和回答正文不再直接进入新一轮限定范围的模型上下文，防止旧来源路径、私有主题或未绑定历史内容绕过当前权限重新外发。

首轮全量回归发现，去掉原始历史正文后，纯“继续讲解”请求即使有当前主题与有效证据，也可能不再产生事实块。final2 将扩展限定为严格整句继续短语，且只使用当前焦点主题键与新授权事实包中规范主题键的交集；仅提及主题的注解不参与，焦点字符串不解析别名。每个实际消费者都独立计算问题范围：教学请求取其剩余事实单元，审核请求只取其选中单元，纯证据回答逐单元计算。贡献的主题链接和冻结主题版本仍进入依赖核验。

这样可以恢复有据可依的继续问答，同时防止前一步来源 A 的主题进入只处理来源 B 的审核或后续教学。若当前问题、授权焦点和新事实仍不足，系统继续要求澄清；不恢复旧问题或答案正文，也不声称保留无限制历史个性化能力。

来源：README.md；evidence/ASTRA_INDEPENDENT_AUDIT.md 的 H1、H2 与 final2 连续问答追加审计。
主要代码：services/answer_relevance.py、services/answers.py、services/orchestration.py、services/conversations.py。

### 学习计划的结构化证据投影

旧路径的问题是具体学习任务在提案、计划、活动、调整和历史读取之间丢失，或由自由文本补写出没有来源支持的目标与能力描述。新投影以已冻结且授权的请求、目标、用户上下文和已审阅出版物构建 text_catalog，任务文本必须用 text_id 和精确 quote 绑定来源。普通摘录最多 600 字符，模块标题摘录最多 120 字符；未知标识、伪造文本、控制字符和指令伪装模式拒绝通过。

模块任务采用封闭的活动类型，明确输入摘录、假设场景、边界和可观察验收项。每个任务最多 8 项输入、6 个场景、8 项边界和 6 项验收。场景操作受限定，重复次数为 1 至 20，序列符号必须是授权文本中存在的单个标识符。场景是待检验输入，不表示代码已经运行，也不表示仓库实际实现了该假设行为。

验收项绑定允许的 rubric 键、目标摘录与可选场景索引，由服务端生成说明。完整焦点事实、适用条件和固定版本引用仍随模块保留，局部引用不被升级为完整事实。任务和计划的能力标记继续为 false；运行时标准仍需要另行授权的练习与实际绑定收据。

未覆盖目标用目标或请求引用、封闭原因码和可选已审阅证据引用表达，不直接把规划器自由文本返回给用户。结果同时列明已投影、未投影和去重数量。缺少 task 的旧提供方走确定性回退，仍限于当前授权请求和所选事实，不能编造任务事实或观测结果；关闭检查时不补加评估。

来源：docs/LEARNING_PROJECTION_REPAIR.md。
主要代码：services/learning_projection.py、services/learning.py、services/learning_ext.py、contracts_learning_ext.py、models_learning_ext.py。

### 活动历史和当前偏好共同生效

模块的具体任务、输入、场景、边界与验收项进入活动提示和冻结评分标准，不能被默认 rubric 静默丢弃。缩小活动事实选择时不能删除冻结任务依赖的事实，也不能扩大模块原有范围。调整保留任务与缺口，重排保留提案清单并遵守先修关系图，缩短会话仍受当前会话上限约束。

计划详情、接受、活动使用与运行结果读取都会重新核验清单完整性、模块哈希、选择闭包、当前固定出版物和保存的目标。发生篡改或证据授权撤回时，阻断依赖的显示或使用，而不是继续返回缓存的来源和目标摘录。

活动创建同时检查冻结任务的真实类型和用户当前偏好。将旧 exercise 任务改名为 understanding_check 或 reading，不能绕过用户后来关闭练习或评估的选择；迁移和运行标准及旧提示也继续接受门禁。

### 授权撤回贯穿策略读取与答案提交

独立审计发现，撤回反馈后只清理候选或进化路径不足以阻断普通会话继续消费旧策略。排队中的会话、冻结策略、撤回第一阶段已提交但清理中断的状态，以及模型审核后至答案提交前的窗口，都可能携带旧授权。

新 policy_inputs 从权威策略、轮次和运行记录导出按角色区分的精确依赖链。新鲜与冻结策略读取都要核验；ModelGateway 在预留调用、派发前和迟到响应处复查；答案分块和完成事务再次核验冻结策略血缘，并持有共享同意锁至提交。撤回栅栏与持久 feedback.withdrawn 事件一并提交，原投影调度器重试幂等清理。

验证覆盖完全撤回后的排队会话、第一阶段中断、派发前、请求进行中、审核后提交前、继承私有来源资助拒绝以及清理恢复。这里证明的是本地服务路径上的授权合同，不能代替 PostgreSQL 多进程锁行为或真实生产工作进程崩溃恢复的验证。恢复活性仍依赖投影调度器实际运行。

来源：evidence/ASTRA_INDEPENDENT_AUDIT.md 的 H3。
主要代码：services/policy_inputs.py、services/policies.py、services/evolution_feedback.py、services/evolution.py、services/answers.py、adapters/model.py、application.py。

### 旧记录和调用收据兼容

新模块、计划投影、草稿和活动 JSON 合同带有 1.6.1 版本标识，不新增 SQL 列或迁移；Alembic head 保持 cf160_features。旧清单和模块不重写，修订保留原草稿格式并增加新清单完整性封装。旧缺口自由文本仅用于恢复原授权目标或请求中的有界摘录，无法投影或过长的文本不回显，重复摘录合并；缺失来源清单不会被补写为具有可靠来源的记录。

未标记的旧回答保留原请求合同以读取既有收据，但旧请求合同不构成新外发授权。审计使用真实原版创建的数据库复现两条路径：带历史焦点的未完成旧任务会向 tutor 新发旧来源正文；已缓存的旧 tutor 段落也会触发一次新 checker 请求。只限制 tutor 不足以关闭第二条路径。

修复后，超出严格呈现字段白名单的旧焦点把 tutor 和衍生 checker 一并标记为 replay_only。网关先核验当前授权并精确查找已完成收据，再于新调用预留之前原子执行仅重放限制；标记不进入请求传输格式或哈希。已有合规收据可保持原哈希与结果、零新增调用地恢复，没有完成收据则以 MODEL_REPLAY_ONLY 拒绝新外发。真实原版数据库的两个原始失败探针复验通过，完整旧收据对继续一致重放。

其他真实跨版本探针由未改动的原版代码生成教学和反思收据，再由修复版恢复，检查零新增提供方调用、原请求哈希不变及返回内容一致。旧未完成请求如请求哈希或引擎版本改变，同样明确拒绝重放，不能自动重新付费。缺少必需私有来源外发授权的旧合同仍然拒绝执行，兼容性不扩大权限。

### 旧导航不改写当前问题

追加审计用真实导入来源和普通定位流程证明：切换到来源 B 时，旧来源 A 的 code_focus.symbol 曾在焦点清理前拼接到当前检索问题，再由 query_rewriter 作为用户问题外发。问题在于把之前派生的来源文本重新分类成用户新写的内容，事后清理来不及阻止外发。

修复后 RetrievalTaskSpec.user_question 保留当前问题原文，不拼接旧导航符号。严格指代定位如需借助符号，仅从当前授权来源的 CodeSymbol 做本地复验查找并隔离缓存，不送入模型。嵌入和重排链路也检查请求隔离；合法的当前问题别名扩展仍可保留。不能解析的指代可能澄清或返回缺口，而非借用无来源绑定的历史正文。

### SDK 安装锁的最小修复

补充运行时测试发现原 coding-agent/package-lock.json 锁定的 base64-js 1.6.0 对应地址返回 404，官方元数据中无此版本。原 integrity 正好对应官方 1.5.1，且上游 ^1.3.0 范围允许 1.5.1。因此只把该项 version 和 resolved URL 改为 1.5.1，保留 integrity 和其余依赖图，不进行顺带升级。

独立结构比对确认只改变这两个字段；新的干净 npm ci 安装 120 个包，安装版本与修正锁一致。真实安装的 SDK 补测使用确定性本地模型，能验证 SDK 和运行时集成，不表示真实提供商 HTTP 或付费推理已通过。原版锁文件与首次安装失败证据仍保留。
