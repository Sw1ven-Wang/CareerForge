本包最终状态以 [交付报告](DELIVERY_REPORT.md)、[1.6.2 验证](docs/VALIDATION_REPAIR_1_6_2.md) 和 `RELEASE_STATUS.json` 为准。1.6.1 原盲测与失败记录完整保留，1.6.2 是另列的已知失败补丁验证，不替换原分数。尚未证明真实职位导入到练习与进化晋升的完整业务闭环。

## 修复范围

- 区分明确检索硬范围与自动主题排序提示，保留旧 `topic_keys` 硬过滤合同、源权限和缓存身份。
- 否定、引用与冲突多动作不再由单个关键词直接决定任务；保持权限、资助与显式焦点边界。
- 反思声明真实传递依赖的数据类别，并在授权撤回、并发与继承策略链路中继续执行严格门禁。
- 学习计划用源/目标锚定的结构化任务呈现具体输入、边界、验收与缺口，贯穿活动、调整、修订和历史读取。
- 新回答合同选择相关事实并预留独立语义/相关性审核预算，安全呈现证据边界并合并缺口。预算与授权不足单独标记，不冒充知识缺失。

完整机制、兼容性和已知限制见本轮报告。没有将单道评测答案写入产品，也没有放宽审核、数据外发或调用预算。

## 回放与权限

跨范围历史问题与回答正文不发送到新一轮模型；继续问答使用当前问题、已授权焦点与新读取的事实包。

新会话和新教学回放使用 `atomic-answer-1.6.1`，未标记的旧回答保留旧请求合同以读取既有收据。已完成历史记录不改写。旧的未完成请求若请求哈希或引擎版本变化，明确拒绝重放，不能自动再次付费。旧合同中包含历史正文或未声明来源焦点的请求仅允许读取既有完成收据；没有完成收据时，在新预约、扣费和模型外发之前拒绝执行。安全的空上下文或有界呈现偏好仍保留原合同。

定位指代只在严格指代问句中使用当前明确来源的本地符号索引，重新核验来源权限、路径、符号和行号，并隔离缓存。旧符号不拼入查询改写器；当前明确符号匹配优先。

`topic_keys` 对直接检索调用仍表示硬范围；新协调结果另携带 `retrieval_topic_keys` 与 `topic_hints`。显式项目焦点与普通不同项目提及时要求澄清；只有未被引用或否定、唯一完整仓库名的明确“切换到 / switch focus to”请求可更新焦点，不通过降级检索或模型建议扩展范围。
