# 项目实现与证据边界

CareerForge 解决的是“岗位要求到本人实践证据”的版本与决策链。六个页面模块共用五类有界工作流；Python 函数负责阶段，PostgreSQL 负责事实、版本、阶段和等待，Celery/Redis 负责投递。取消、租约、完整条件与人工确认都在业务事务中控制。

关键设计可从代码与证据复核：

1. LearningPlan 的草稿/采纳版本不可变，子集采纳复制成员并更新指针，不创建任务。
2. BuildTask 的 revision、内容版本和当前 Submission 分开；条件由服务器冻结完整集合。
3. Assessment 是不可变原提案；分项自验追加 Review/Confirmation，旧提案不覆盖新提交。
4. 原文引用由 commit、路径、原始行区间和哈希定位；AST 只解析，不执行参考代码。
5. Outbox、稳定阶段键、DB 时钟租约与 epoch 处理重放和失联；并发确认锁后刷新 ORM 对象。

借鉴范围：保存的 LangGraph 代码用于学习版本化持久化接口，保留 MIT 许可证；未移植其运行引擎或 checkpointer。其他开源项目见原始决策文档，只能按实际阅读证据介绍，不能把其已有能力称为全部自研。

离线对照覆盖一个固定仓库的四个定位查询和四种条件集合。两项中文查询依赖显式别名才命中定义；这不是语义检索质量结论，更不是独立留出评测。没有实测收益的向量库、额外角色、外部 Langfuse 和 MCP 保持关闭。
