# 1.6.4 有界引用消歧合同

## 启用与兼容

仅 `execution_contract_version=bounded-build-execution-1.6.4` 且
`quote_correction_contract={"version":"bounded-quote-correction-1.6.4","max_attempts":1}`
的冻结执行启用此流程。旧 manifest 不自动升级，不新增纠正调用、不改原请求或收据。
错误或不完整的新标记直接失败。每来源 analysis final 预留一次额外调用，
每单元 review final 预留一次；不按同一 analysis 输出中的单元重复预留。

## 原引用合同与只读预检

引用仍只有 `read_id` 与 `quote`，不新增 offset 字段或持久化位置迁移。
`quote` 必须是本角色、本执行、同一冻结 bundle 内已经实际读取的连续原文，
并在该 read 内逐字符唯一，包括重叠匹配。支持、反证、独立审核证据、审核反证均预检。
预检不写 SourceRead、Evidence 或 Publication，不新增读取、访问范围或读预算。

只有重复文本可以进入消歧。权限撤回、取消、超时、来源/读取哈希失败、缺失引用、
跨角色或跨执行读取、冻结 bundle 不一致等错误均直接停止，不能作为模型纠正反馈。
只有已授权已读来源的文本进入诊断；错误与通用阶段记录不复制私人 JD。

每份诊断完整枚举所有候选，位置采用相对 read 的零基 Unicode 码点半开区间，
行列是一基位置，按照源读取窗口的 `splitlines(keepends=True)` 边界显示。
候选只是尚未接受的位置，不是已批准证据。单引用及整份反馈合计最多 256 个候选，
完整诊断最多 64,000 UTF-8 字节；超过任一上限报 `QUOTE_FEEDBACK_LIMIT`，
不截断候选、不自动选择、不声称唯一。

## 行分隔支持范围

新执行的持久证据行位置仍沿用原 LF 计数合同，保留既有 LF 尾换行语义。
为避免新引用被发布为错误的源行，预检只允许引用文本中行分隔为 LF 或 CRLF 的 read。
若该 read 包含 CR-only、垂直制表、换页、U+001C/U+001D/U+001E、U+0085、
U+2028 或 U+2029 分隔符，报 `QUOTE_LINE_CONTRACT`，不发起纠正、不发布该输出。
只读诊断仍可准确展示这些分隔的候选，但不能赋予证据或发布资格。
完整支持这些输入需要另一个版本化持久位置合同，不在本轮扩张；旧记录、收据不改写。

## 唯一一次模型纠正

第一次 final 结果完整保留。纠正具有独立固定阶段键与请求哈希，使用相同模型角色、
输出 schema、data_classes 和 access_dependencies，通过同一计量、权限、隐私与预算网关。
诊断保存后、纠正前重新校验源、读取、冻结 bundle、租约、取消与授权，不复用失效材料。

纠正请求仅包含完整原结构化 response、全部诊断、冻结 bundle 的全部原 read 回执、
role/session 与原完整 bundle 哈希，以及轻量身份和语义。Reviewer 原有逐 claim 字典
原样保留，包括 statement、conditions、criticality，以及存在时的 kind、适用范围等字段；
Analysis 语义已在完整原 response 中。搜索 trace、展开的 analysis_evidence、render_ast、
原研究任务/JD、覆盖锚点与历史更新上下文不重复发送。所有来源和命题均作为不可信 JSON
用户资料，不提升为 system 指令。固定纠正 system 只要求消歧，不重新研究或改变审核决议。

模型必须自行依据语义与已读上下文给出连续唯一摘录，不能由产品代选第一个候选。
只允许修改诊断所列 JSON pointer 的 `read_id/quote` 对象；其他字段、引用数量、
命题、条件、反证、审核结论与任务覆盖必须逐项不变。全部引用再次预检后，仍须通过
原 `evidence_from_read`、`evidence_dict`、独立审核、覆盖与发布门禁。
无法纠正、仍有歧义、缺失引用或修改其他字段都停止；不得发起第二次纠正。

精确完成收据可幂等重放；相同阶段但不同请求或结果不确定时不能重发。
纠正消耗正常子执行、根执行与 funding 预算，不免除截止时间、撤权或取消约束。

## 重叠匹配安全收紧

旧 `str.count` 会把 `aaaaa` 中的 `aaaa` 错当唯一；新诊断、证据写入和证据重验
统一枚举重叠位置。旧数据中此类假唯一证据重验时 `EVIDENCE_HASH` 失败，不改写旧行。
这项更严格的唯一性校验也适用于旧记录，不以兼容为由继续接受歧义。
本次 LlamaIndex 和 Agents 的真实错误则是两处非重叠重复，不依赖此额外修复。

## 已验证范围

作者测试覆盖两处冻结源码故障的精确位置、四类引用、完整反馈上限、权限/哈希失败、
计量、撤权/取消/超时、一次纠正、幂等、旧 wire、最小上下文、注入隔离和实际构建拒绝
不支持的行分隔。测试中的模型响应明确为 synthetic；未据此宣称真实模型纠正质量通过。
固定故障 JSON 的纠正请求体积由离线结构测量确认，未发起模型请求。
