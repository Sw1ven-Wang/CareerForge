# 1.6.6 提交后的模型评价候选

POST `/api/v1/learning/assessments` 接收 namespace_id、funding_id、attempt_id、idempotency_key。只有本人的已提交、未改变的学习尝试可以启动。一项明确预算的模型调用使用冻结题目、任务、rubric、已审核事实及源码引用，返回逐项判断；结果经现有 run API 读取。

## 不可越过的边界

- 原文提交、题目、源码、模型解释均为不可信资料。非 unknown 判断必须逐字引用本次提交；肯定性静态判断必须引用当前事实 ID。仅通过这些机械检查不意味着语义正确。
- 输出是 `model_assessment_candidate`，始终保留 `requires_review=true`、`competence_verified=false`。不会创建真人或自评记录，不会更新掌握程度、学习计划或策略。
- 每个 rubric ID 必须恰好出现一次，不接受新造或重复事实 ID。题目和任务进入冻结输入，不只看答案文本。
- 运行观察仅来自同一用户、工作区版本、文件清单和批准摘要绑定的完成回执。纯文字“全部通过”不能填补运行证据。合成沙箱回执单独标为 synthetic，不能提升运行项为已证明。
- 帮助条件由已有尝试和服务端记录投影，外部帮助只能表述为本人声明，不监控别的设备，也不把 assisted/unknown 改成 independent。
- 执行前、执行后和结果读取时复核当前授权、来源、题目、提交和模型回执。撤销、篡改或擦除后拒绝沿用结果。
- 未结束的独立练习阻止模型评价；排队中的评价也阻止新开启独立尝试，避免隐式辅助。

## 本次验证

新增 14 项机制回归覆盖重复请求、缺失事实、错误逐字引用、重复 rubric、提交改变、源码撤销、回执擦除、伪称真人评价、合成运行回执、执行摘要改变、提交撤销及独立练习互斥。全部通过。使用显式测试模型/沙箱，不是模型正确率、真实代码运行或真人能力评价结果。

真实模型桥接试验的结果和环境限制单独记录在交付报告中；不能用机制测试替代真实模型或 Docker 验收。
