## Defect and preserved evidence

The conversation, retrieval, read validation and task-result metadata all treated that as an unconstrained symbol lookup. A correct LOCATE/direct-tool route therefore still returned real source from another file.

## Four-service change

`explicit_source_paths.py` adds `navigation_path_request` and the internal guard version `locate-path-guard-1.6.5.2`. The candidate001 `requested_source_path` grammar is unchanged. This is not a three-verb allowlist expansion.

When the old grammar cannot confirm a target, the new guard independently notices path-like syntax in the original user question after routing has established LOCATE. It returns `requested_source_path_attachment_unconfirmed`, not an exact target or a file-existence claim. Whole quoted instructions, fenced code, quoted example text and recognized contextual mentions remain data. A literal quoted path token is still eligible for checking. Ordinary non-LOCATE filename discussion does not activate this additional guard. Slash-relative candidates do not need an extension. An unsupported bare dotted candidate (such as `Inspect missing.py` or `Inspect AgentRun.next`) yields a separate `requested_source_target_ambiguous` clarification asking whether the target is a path or symbol. It does not guess type by extension, case or source availability. Under the final amendment, a bare dotted target also clarifies with a recognized verb, for example `Locate AgentRun.next`. Explicit `Locate symbol AgentRun.next` retains symbol navigation. A slash token is repository context only when explicitly labeled repository/project/仓库/项目; a navigation verb or a following symbol does not prove that type. See `AMENDMENT_002.md` for the authorized positive-input migrations and legacy controls.

`conversations.py` writes `focus.source_path_guard` itself on new submissions, overwriting any inherited value. The strict TurnInput schema has no client field for this marker. The coordinator schema and model prompts are unchanged, and model `code_focus_ref` is not used as authority. Process checks the guard after normal routing and before retrieval; unresolved candidates produce a server clarification, zero substitute reads and `task_satisfied=false`. The same check runs on durable resume. `_navigate_source` independently rejects navigation by returning clarification for an unconfirmed target, even when handed real legacy selection evidence. A confirmed target still requires the original frozen snapshot/path binding plus a matching selection guard version.

`retrieval.py` applies the guard to LOCATE requests before candidate selection, filtering and rewrite. The guard version participates in cache identity and is recorded in the path selection manifest/result. Current direct retrieval defaults to the new guard. An explicit internal `None` supports old durable processing; it is not a field accepted from the retrieval API body and cannot authorize a substitute read on a newly guarded turn.

`answers.py` applies the frozen turn guard to any raw-source commit and every existing replay validation surface, regardless of whether orchestration was bypassed. A genuine same-turn receipt from an alternative file cannot commit when the original target is unconfirmed. Omitting the navigation receipt marker does not bypass this check. Existing source permission, hash, identity and receipt checks remain intact.

## Compatibility and permissions

- A turn with no original `source_path_contract` retains pre-path-contract semantics.
- A candidate001 turn carrying only `explicit-source-path-1.6.5` and no new guard retains its original semantics and completed receipts unchanged. Old wrong-file receipts are not retroactively presented as repaired results.
- Newly guarded, already-supported exact paths retain the candidate001 parser, server-frozen source IDs and selection/commit/replay binding. No source-discovery or permission rule is broadened.
- An unconfirmed candidate yields a source-independent clarification. It does not inspect file contents, excluded files, private source catalogs or nearby names and does not assert any snapshot missingness.
- Cancellation, leases, policy checks, funding, page limits, exact-source paging, revocation and cache/privacy invalidation contracts are unchanged. Global workflow status is unchanged: successful delivery of a clarification may still be `succeeded`, but its task result is explicitly not completed.
- The guard does not make a general natural-language authorization classifier, infer an exact file from ambiguous repository/file references or repair malformed paths. It closes the confirmed path-like-candidate-to-unrestricted-LOCATE fallback. A supported exact target is resolved only under the existing source/path contract; otherwise the added guard can only require clarification.
